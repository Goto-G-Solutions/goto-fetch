# Changelog

Each release lists what changed for people using the package. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Until 1.0, a minor version (0.x) may change the public interface.

## 0.1.0

The first release.

- `Client`: one API's base URL, headers, timeouts, retries and authentication, with JSON and paginated records.
- Paging: next links in the body (`NextLink`) or the `Link` header (`HeaderLink`), cursors in the query or the body (`Cursor`), or limit and offset (`Offset`), with an optional count, and progress logged per page. `records(method="POST", json=...)` pages a POST search, with `retry=True` when it only reads. Paging styles see each page's body and response (`Fetched`) and say what to fetch next (a URL, or a `PageRequest`).
- Authentication: fixed token headers (`token_headers`), and access tokens that renew themselves (`TokenRefresh`), safely across threads, before they expire (by `expires_in` or a JWT's own expiry). New tokens come from any `Login`: `PasswordLogin`, OAuth2 `ClientCredentials`, or your own.
- Records: `get_path`, `select`, `flatten` and `explode` reshape nested JSON without a dataframe library.
- Dataframes: `to_frame` in polars, pandas or pyarrow through narwhals, evening out mixed types at every depth, and `latest_per_key`.
- Extension points: `json_decoder` (msgspec when installed), typed records with `records(model=...)`, `default_backend`, retry policies (`RetryPolicy`, with `Retry` built in), and `Client(http=...)` for an httpx2 client of your own.
- Defences learned from other libraries' bug histories (dlt's especially): an empty page ends a run even when the API promises more (`stop_on_empty=False` to turn off); a next-page path missing from the first page is warned about; a cursor must be one value; an empty body or 204 is an empty page; counts written as digits are read; a connection dropped mid-response is retried; secrets in URLs (`api_key=`, `access_token=` and the like) are hidden in errors and log lines (`redact_url`, `RedactFilter`). From Singer SDK, Airbyte, httpx and pandas histories too: `params=` merge into a query already in the endpoint; a 429 or 5xx from a token endpoint is retried; `expires_in` of 0, negative or odd values is ignored and digits as text are read; the expiry margin is capped at half a token's life; an empty 200 is an error (only 204 and 205 are empty pages); gzip without `Content-Encoding` is unpacked; non-JSON errors say the content type and how the body began; `flatten` quotes keys that would collide.
- Incremental fetching: `records(incremental=Incremental(field, param))` asks only for records from the last run's highest value on, in the query or a POST body, and passes over those already seen. Its `state` is plain JSON, moves on only after a complete run, and is never saved by the package itself. Works when the API has no filter (`param=None`), with numbers or ISO timestamps, nested fields, and `send_as` for filters in another form. `testing.changes_api` is a fake API that filters by a field. `tracked_run` saves the state only when the whole run, storing included, worked; `SqliteState` keeps it in an SQLite file with no extra package, and any `StateStore` (`get`, `put`) can replace it (`testing.MemoryState`, `testing.check_state_store`).
- Change detection: `Changes(key, ignore=...)` fetches everything and passes on only new and changed records, by a hash of each, and lists the keys that disappeared (`deleted`), for APIs without a trustworthy change field. `records(incremental=...)` and `tracked_run(store, name, tracker, ...)` take either tracker (`Tracker`).
- Response checks: `Client(check=...)` catches errors an API reports in a 200 body, so a page holding an error stops the run instead of passing for an empty last page. `error_at(path)` is built in; a check finds a `Problem`, permanent (fails at once) or temporary (retried like a 503). `FetchPlan(error_path=...)` and the explorer's Error path field use it.
- Interfaces are Protocols (`Paging`, `RetryPolicy`, `Login`, `ResolvesUrls`), checked by type checkers; `with_query` helps paging styles set query parameters.
- Building blocks for loops of your own: `paginate` (which pages by any request, such as a POST body, with loop protection by `request_key` or your own key), `read_page`, `Client.json_body` and `converter`.
- Logging: silent until switched on (`enable_logging`, `logging_to`); every line is an event with data (`record.event`, `record.data`), including why paging stopped and why tokens were renewed; `Client(name=...)` labels a client's lines, including those of your own pieces (`log_event`, `ClientFilter`).
- `FetchPlan`: describe a fetch once, run it, or write it as a script.
- Scraping (the `scrape` extra), and the explorer notebook (the `explorer` extra), which covers the library's auth (header tokens, access/refresh with login, OAuth2 client credentials) and paging styles, and writes the fetch as a script.
- `api_explorer.testing`: fake APIs for testing code that fetches from APIs (next link, limit/offset, cursor, Link header, a simplejwt-style token server, fixed pages and responses), `flaky` to inject failures, and `FakeApi`, which remembers every request. For pieces you build on the interfaces: `fetched` builds a page to test a paging style on its own, and `check_retry_policy` and `check_paging` check the promises every policy and style must keep.
