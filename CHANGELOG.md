## [0.1.0]

The first release.

### Added

- **Transports:** the library that sends is a choice. `Transport` is the interface (`send`, `close`), on the package's own `Request` and `Response` (`api_explorer.http`); `Urllib3Transport` is the default and `Httpx2Transport` (the `httpx2` extra) offers HTTP/2 and an `httpx2.Client` of your own. `Client(timeout=Timeout(connect=5, read=60))` sets the connect and read limits apart. `Limited(transport, RateLimit(n))` keeps every request to a rate, retries and logins included, for servers that can't take a fast run (`FetchPlan(rate_limit=...)` and the explorer too). `testing.serve` runs a fake API over real HTTP on this machine, and `testing.check_transport` checks a transport's promises.
- **Client:** one API's base URL, headers, timeouts, retries and authentication, with JSON and paginated records (`records`). `params` merge into a query the endpoint already has. A response check (`check=`, built in: `error_at`) catches errors an API reports inside a 200, so a page holding one stops the run instead of passing for an empty last page.
- **Paging:** next links in the body (`NextLink`) or the `Link` header (`HeaderLink`), cursors in the query or a POST body (`Cursor`), limit and offset with an optional count (`Offset`), and pages by a sorted field (`Keyset`), which data changing during a run can't make skip a record. `records(method="POST", json=...)` pages a POST search. Building blocks for loops of your own: `paginate`, `follow`, `read_page`, `with_param`, `request_key`; a loop raises `PaginationLoop`.
- **Retries:** `Retry` (attempts, statuses, methods, backoff, `Retry-After`) or any `RetryPolicy`. Network errors, dropped connections, 429 and 5xx are retried, for idempotent methods unless a call says otherwise, and so are temporary failures at a token endpoint.
- **Authentication:** fixed token headers (`token_headers`), and access tokens that renew themselves (`TokenRefresh`) before they expire, safely across threads, with refresh tokens that rotate. New tokens come from any `Login`: `PasswordLogin`, OAuth2 `ClientCredentials`, or your own; an `Auth` of your own (`auth_flow`, as in httpx) works over any transport.
- **Incremental fetching:** `Incremental` asks only for records from the last run's highest value of a field on, and passes over those already seen; `Changes` fetches everything and passes on only new and changed records, by a hash of each or a `fingerprint` of your own, and lists deleted keys. Both are `Tracker`s, and so is any object with `apply`, `track` and `state`. A tracker's state moves on only after a complete run, and `tracked_run` saves it only when the run and its storing both worked, in any `StateStore` (`SqliteState` built in).
- **Storage:** `Warehouse` is the interface (`write`, `read`), with promises every warehouse keeps: one write is all or nothing, a key replaces rows, deletions are removed only after storing, and no value is lost. `DuckDBWarehouse` (the `duckdb` extra) and `SqliteWarehouse` keep tables and tracked runs' state in one file; columns follow the records, nested values become JSON, and a column whose values change type is widened. `write_run` and `SqlTables` build a warehouse for another SQL database.
- **Records and frames:** `get_path`, `select`, `flatten` and `explode` reshape nested JSON without a dataframe library; `to_frame` builds a polars, pandas or pyarrow frame through narwhals, evening out mixed types at every depth, and `latest_per_key` keeps one row per key.
- **Extension points:** JSON parsing (`json_decoder`, msgspec when installed), typed records (`records(model=...)`), the dataframe library (`default_backend`), and how requests are sent (`Client(transport=...)`). Every interface is a Protocol or a function type, checked by type checkers.
- **FetchPlan:** describe one fetch once, then run it, store it (tracked or not) or write it as a uv script that does the same, with secrets read from environment variables.
- **Logging:** silent until switched on (`enable_logging`, `logging_to`); every line is an event with data (`record.event`, `record.data`), stamped with the client's name, with secrets in URLs hidden.
- **Testing kit** (`api_explorer.testing`): fake APIs that page, filter, fail and authenticate like real ones (`next_link_api`, `offset_api`, `cursor_api`, `link_header_api`, `changes_api`, `keyset_api`, `TokenServer`, `json_pages`, `replies`, `flaky`), `MemoryState` and `MemoryWarehouse`, and checks for pieces you build: `check_paging`, `check_retry_policy`, `check_tracker`, `check_state_store`, `check_warehouse`.
- **Guides** for each piece ship with the package (`python -m api_explorer.docs`), with runnable examples, a page on building your own pieces, an Agent Skill (`SKILL.md`), and `llms.txt` in the repository.
- **Scraping** (the `scrape` extra) and the **explorer** notebook (the `explorer` extra), which covers the library's auth, paging, tracking and storage, and writes the fetch as a script.
- **Defences** learned from the bug histories of dlt, Singer SDK, Airbyte, httpx and pandas, each guarded by a test: an empty page ends a run; a next-page path missing from the first page is warned about; a cursor must be one value; an empty 200 is an error while 204 and 205 are empty pages; gzip without `Content-Encoding` is unpacked; odd `expires_in` values are ignored; secrets in URLs, passwords included, never reach messages or logs.
